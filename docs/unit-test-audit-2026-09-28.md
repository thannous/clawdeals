# Unit-test audit — 2026-09-28

Reviewed all 413 original test files with three parallel agents and a cross-review. Deleted 197 files, pruned 158 retained files, and kept 58 intact. 216 files remain (215 Vitest files and one Python SDK test). No application code or E2E spec was changed. Existing unrelated working-tree changes were preserved; nothing was committed or deployed.

## Decision rule

Keep an isolation test only when its assertions detect a concrete failure missing from the existing E2E tests. Delete duplicated happy paths, static copy/source/configuration checks, and tests that only restate their mocks. Keep failure injection, serialization limits, secret leakage, races, partial migrations, and actual client/worker boundaries when the E2E harness cannot exercise them. Tests removed from mixed suites were redundant; the retained failure modes are listed below.

E2E comparisons are source inspection. They do not claim that the complete database suite passed. The UI suite includes stubbed APIs, so UI passes do not establish persistence, database authorization, or distributed atomicity. Historical migration text matching was removed without claiming that current E2E proves every privilege or historical backfill; those remain runtime coverage gaps. Report-retention tests mocked their own cutoffs and REST client, so removing them likewise does not establish working retention.
